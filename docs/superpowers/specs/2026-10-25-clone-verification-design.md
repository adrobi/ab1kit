# Проверка клонов, точность анализа пиков и новый интерфейс — дизайн

Дата: 2026-10-25 · Статус: согласован в обсуждении, ждёт ревью спецификации

## 1. Цель и сценарий

Главный сценарий ab1kit после этой работы — **проверка клонов одного
конструкта**: в лаборатории отобрали 4–12 колоний, каждую отсеквенировали
1–4 праймерами; нужно быстро понять, какой клон правильный, а если нет —
где и какая ошибка. Остальные сценарии (генотипирование ожидаемых SNP, поиск
мутаций, просмотр/экспорт одного рида, батч-QC) сохраняются как есть.

Пользователи — биологи, не биоинформатики. Платформа — Windows (как сейчас),
лицензия MIT.

**Критерий успеха:** пользователь перетаскивает файл конструкта и папку с
ридами, задаёт регион проверки и за минуту видит по каждому клону вердикт,
а по каждому расхождению — хроматограммы всех ридов в этой позиции.

### Принятые решения

| Вопрос | Решение |
| --- | --- |
| Главный сценарий | Проверка клонов (B); остальные сохраняются |
| Формат конструкта | Основной — FASTA (без аннотаций); также GenBank и SnapGene `.dna`; Benchling — нет |
| Размер сессии | Один конструкт, 4–12 клонов × 1–4 рида |
| Группировка ридов в клоны | Автоматически по имени файла + ручная правка; свой шаблон-regex в настройках |
| Что проверяется | Регион, заданный пользователем; вне региона расхождения видны, но на вердикт не влияют |
| Архитектура UI | PySide6 Widgets, обновлённый стиль; без переписывания на QML/веб |
| Раскладка главного экрана | «Матрица»: все клоны строками на общей оси с референсом |

## 2. Ядро (`chrom_core/`, без зависимостей от Qt, покрыто pytest)

### 2.1 `reference.py` — загрузка конструкта

- `load_construct(path) -> Construct`; формат по расширению (`.fa/.fasta/.fna/.txt`,
  `.gb/.gbk/.genbank`, `.dna`) с проверкой содержимого; чтение через
  `Bio.SeqIO` (`fasta`, `genbank`, `snapgene`). Берётся первая запись.
- `Construct`: `name`, `seq` (верхний регистр, IUPAC), `circular: bool`,
  `features: list[Feature]` (может быть пустым).
- `Feature`: `name`, `kind` (`CDS`, `promoter`, `primer_bind`, …), `start`,
  `end` (0-based, полуоткрытый), `strand` (+1/−1); фичи через начало
  координат поддерживаются (`start > end` означает обёртку).
- `circular`: из файла для GenBank/SnapGene (topology); для FASTA — `True` по
  умолчанию, переключается пользователем.
- Существующий `align.parse_sequence` остаётся для вставки текстом
  (результат — `Construct` без фич, `circular=True`).

### 2.2 `align.py` — кольцевой референс

- Новая функция `align_to_construct(read, construct) -> ReadAlignment`.
  Для линейного — вызывает существующий `align_read`. Для кольцевого —
  выравнивает на `seq + seq[:len(read) + 50]`, затем приводит все
  координаты (`ref_start/ref_end`, `ref_to_read`, `differences`) по модулю
  длины. Для обёрнутого выравнивания `ref_end` может быть меньше
  `ref_start`; добавляется метод `covers(pos)` и `covered_positions()`.
- `align_read` и его тесты не меняются. `MAX_REFERENCE_LENGTH` (100 т.п.н.)
  действует на исходную длину конструкта.

### 2.3 `peaks.py` — анализ вторичных пиков (выносится из `snps.py`)

- `channel_baseline(chrom, i, span=20) -> dict[base, float]` — медиана
  высоты пиков каждого канала среди ~20 ближайших вызванных баз этого
  канала; нормирует разную яркость красителей.
- `peak_window(chrom, i)` — половина расстояния до соседних пиков (не
  меньше 2 точек) вместо фиксированных ±5.
- `secondary_peak(chrom, i) -> SecondaryPeak(base, ratio, primary_base)` —
  на **любой** позиции: нормированная высота сильнейшего канала вне
  вызванной базы, делённая на нормированную высоту вызванной.
- `snps.py` и `verify.py` переходят на `peaks.py`; публичные сигнатуры
  `call_snps`, `verify_expected`, `peak_heights` сохраняются (последняя
  остаётся как обёртка). Добавляется `scan_secondary_peaks(chrom,
  alignment, min_ratio)` — поиск гетерозигот/смесей по всему выровненному
  риду, включая позиции, где вызвана референсная база.

### 2.4 `clones.py` — проверка клонов

**Группировка.** `group_reads(paths, pattern=None) -> Grouping`.
- По умолчанию: имя файла без расширения делится по `_`, `-`, `.`, пробелу;
  метка праймера — последний токен, совпавший со словарём (`F`, `R`, `FW`,
  `REV`, `FWD`, `T7`, `T7term`, `SP6`, `T3`, `M13F`, `M13R`, `pUC-F`, … —
  регистр не важен; словарь расширяется в настройках); если совпадений со
  словарём нет — последний токен. Клон — исходная подстрока имени **до**
  токена праймера (с сохранением исходных разделителей), из которой убраны
  хвостовые разделители, номер порядка праймера (`^\d$` непосредственно
  перед праймером) и ведущая позиция лунки планшета (`^[A-H]\d{1,2}$`).
  Если после этого клон пустой — файл попадает в «без клона».
  Пример: `Achl_ACHLO006-09_1_F` → клон `Achl_ACHLO006-09`, праймер `F`.
- Свой шаблон — regex с именованными группами `clone` и `primer`.
- Нераспознанные файлы → группа «без клона» (в проверку не идут, пока
  пользователь их не назначит).
- `Grouping` сериализуется вместе с ручными правками.

**Проверка.** `verify_clone(construct, region, reads, params) -> CloneReport`.
- `region`: `(start, end)` в координатах конструкта, обёртка через начало
  допустима для кольцевого.
- Для каждого рида: текущая версия с учётом сессии правок
  (`<файл>.ab1kit.json`), выравнивание `align_to_construct`. Рид с
  `alternatives > 1` помечается «неоднозначно» и не участвует в вердикте.
- **Покрытие** по позиции региона: число ридов, покрывающих её с Q ≥ `min_q`
  (по умолчанию 20), отдельно по цепям.
- **Расхождения** (`CloneDifference`): замены, вставки, делеции из
  выравниваний всех ридов, объединённые по позиции и типу; для каждого —
  `support` (ридов с этим расхождением и Q ≥ `min_q`), `against` (ридов,
  видящих референс с Q ≥ `min_q`), статус `confirmed` (support ≥ 1,
  against = 0) / `disputed` (support ≥ 1, against ≥ 1) / `low_quality`
  (support = 0, есть только низкокачественные).
- **Эффект** (если в конструкте есть CDS, перекрывающая позицию): для
  замены — синонимичная / миссенс (`D45N`) / стоп; для вставки/делеции —
  «сдвиг рамки» или «вставка/делеция в рамке». Без аннотаций — пусто.
- **Смешанность:** позиции региона, где `secondary_peak.ratio ≥ het_ratio`
  (по умолчанию 0.40) хотя бы в одном риде с Q ≥ `min_q`.

**Вердикт** (первое сработавшее правило):
1. `no_data` — ни один рид не выровнялся (или все неоднозначны);
2. `mixed` — ≥ `mixed_min_positions` (по умолчанию 3) позиций со вторым пиком;
3. `errors` — есть `confirmed` или `disputed` расхождение в регионе;
4. `incomplete` — есть позиции региона без покрытия с Q ≥ `min_q`;
5. `ok`.

Дополнительно в отчёте: доля региона, покрытая обеими цепями.

Пороги (`min_q`, `het_ratio`, `mixed_min_positions`) — в `VerifyParams`,
значения по умолчанию выше, настраиваются в интерфейсе.

### 2.5 Проект и отчёты

- `project.py`: файл `.ab1proj` (JSON) — путь к конструкту (относительный,
  если рядом), `circular`, регион, список ридов с привязкой клон/праймер,
  ручные правки группировки, `VerifyParams`. Версионируется полем `version`.
- Отчёт `clone_report_csv` / `clone_report_xlsx` (openpyxl): лист «Клоны»
  (клон, вердикт, покрытие региона %, обе цепи %, расхождений, риды) и лист
  «Расхождения» (клон, позиция, тип, ref→read, эффект, за/против, статус,
  примечание).

### 2.6 Производительность

Сценарий 12 клонов × 4 рида на конструкте 10 т.п.н. замеряется тестом;
порог фиксируется по замеру с запасом ×2. В интерфейсе всё выполняется в
фоне, поэтому длительность влияет на ожидание, но не на отзывчивость.

## 3. Интерфейс (`ui/`)

### 3.1 Структура окна

- Две вкладки-режима: **«Проверка конструкта»** (новый главный экран) и
  **«Просмотр рида»** (нынешний просмотрщик с панелями анализа, проверки
  SNP и батч-QC).
- Двойной клик по риду/расхождению → рид открывается в «Просмотре рида»;
  после правки проверка пересчитывается.

### 3.2 Экран «Проверка конструкта» (раскладка «матрица»)

1. **Строка-сводка:** имя конструкта, длина, кольцевая/линейная, регион;
   счётчики клонов по вердиктам — каждый работает как фильтр.
2. **Матрица:** сверху дорожка референса (фичи, если есть; рамка региона —
   задаётся протяжкой мышью или вводом координат). Ниже по строке на клон:
   покрытие (цвет — одна/две цепи, бледный — Q < 20), метки расхождений
   (цвет по статусу), плашка вердикта. Колёсико масштабирует общую ось.
3. **Детали:** по клику на метку — хроматограммы всех ридов клона в этой
   позиции друг под другом, референс сверху; рядом таблица расхождений
   клона (позиция, ref→read, эффект, за/против, статус).
4. **Пустое состояние:** подсказки «перетащите файл конструкта» и «…папку с
   ридами» вместо пустых панелей.

### 3.3 Окно группировки

Таблица «файл → клон, праймер» с правкой ячеек; поле своего шаблона с
мгновенным предпросмотром; группа «без клона» выделена.

### 3.4 Внешний вид

- Единая QSS-тема поверх Fusion (светлая/тёмная), общая палитра статусов:
  зелёный — подходит, красный — ошибки, жёлтый — неполное покрытие,
  фиолетовый — смесь, серый — нет данных; легенда в строке-сводке.
- Иконки на панели инструментов: набор SVG под MIT/Apache-2.0 в
  `ui/icons/` с файлом лицензии.
- Полоски качества раскрашены по Q (с легендой).
- Колонки таблиц подстраиваются под содержимое; полный текст длинных ячеек
  во всплывающей подсказке.
- Исправления найденных ошибок: английское примечание в русском UI
  (`verify.py` отдаёт непереведённую строку); «Ср. Q = 0» в батч-режиме
  для ридов без данных качества → «—».

### 3.5 Внутреннее устройство UI

- `main_window.py` (1163 строки) разбивается: оболочка окна и меню;
  `ui/read_view/` — существующие панели (диалоги поиска/обрезки, анализ,
  проверка SNP, батч), каждая в своём файле; `ui/construct/` — сводка,
  матрица, панель деталей, диалог группировки.
- Фоновые задачи: обёртка над `QThreadPool`/`QRunnable` с сигналами
  прогресса, результата, ошибки и флагом отмены. Через неё — проверка
  клонов, сканирование папки, отправка в BLAST.
- Все новые строки — через `_()` с переводами в `translations_en.py`.

## 4. CLI (`chrom_cli.py`)

- Без аргументов или с путём — запуск GUI (как сейчас).
- `ab1kit verify-clones --construct FILE [--region A-B] [--linear]
  [--pattern REGEX] READS_DIR -o REPORT.(csv|xlsx)`; код возврата 0, если
  есть хотя бы один клон `ok`, иначе 1; 2 — ошибка входных данных.
- `ab1kit qc READS_DIR [-o CSV]` и `ab1kit export READS_DIR --trim
  [--fasta|--fastq] -o DIR` — над существующим `batch.py`.
- Реализация на `argparse`; подкоманды распознаются по первому аргументу,
  путь к файлу/папке по-прежнему открывает GUI.

## 5. Обработка ошибок

- Нечитаемый `.ab1` или невыровнявшийся рид не прерывает проверку: рид
  помечается в таблице с причиной, остальные обрабатываются.
- Пустой регион, регион вне конструкта, конструкт больше лимита — понятное
  сообщение до запуска.
- Неоднозначное выравнивание (повторы) — рид помечен «неоднозначно», в
  вердикт не идёт.
- Отмена фоновой задачи сохраняет предыдущий результат.
- Битый или устаревший `.ab1proj` — сообщение и открытие без проекта.

## 6. Тестовые данные и тесты

### 6.1 Данные

- **Реальные риды:** sangeranalyseR (MIT), `inst/extdata/Allolobophora_chlorotica`
  — 4 образца × F/R = 8 файлов (~1,7 МБ) в `tests/data/real/` с README
  (источник, коммит, лицензия).
- **Референсы с NCBI:** запись COI *A. chlorotica*, соответствующая
  образцам (accession подбирается BLAST-ом ридов и фиксируется в README), и
  pUC19 (L09137, GenBank, кольцевая, с аннотациями). Скачиваются один раз
  `scripts/fetch_test_data.py` (E-utilities) и коммитятся; тесты сеть не
  используют.
- Наборы gear-genomics (GPL-3.0) не используются.

### 6.2 Контролируемая истина

- **Ошибки клона:** в копию референса вносится известная замена /
  вставка / делеция; реальный рид даёт расхождение в известной позиции.
- **Смесь:** полусинтетическая копия реального рида, в которой под
  выбранной позицией в другой канал добавлен пик формы соседнего реального
  пика заданной высоты (30% и 50%). Генерируется в фикстуре, явно помечена.
- **Набор клонов:** «подходит» (реальные риды, неизменённый референс),
  «ошибка» (изменённый референс), «неполный» (обрезанный рид),
  «смесь» (полусинтетика), «нет данных» (рид другого гена).

### 6.3 Проверки

- Каждая внесённая ошибка найдена с верными позицией, типом, `support`.
- Ноль ложных расхождений в регионе на неизменённом референсе при Q ≥ 20.
- Второй пик 30% — не смесь, 50% — смесь (при `het_ratio` 0.40).
- Кольцевое выравнивание: рид через начало координат повёрнутого pUC19
  даёт непрерывное покрытие и верные координаты.
- Группировка имён sangeranalyseR и синтетических имён (`cl3_T7`, `A05_K3-F`,
  `clone12.rev`); свой regex.
- Чтение FASTA/GenBank/SnapGene. BioPython не умеет писать `.dna`, поэтому
  берётся образец из `Tests/SnapGene/` набора тестов BioPython (Biopython
  License, как и нынешние `examples/`), с указанием источника в README.
- Регрессия: существующие тесты `snps`/`verify` проходят после выноса в
  `peaks.py`; плюс прогон на реальных ридах.
- Производительность 12 × 4 на 10 т.п.н. (порог по замеру).
- GUI smoke в offscreen: экран проверки открывается, проект загружается,
  матрица рисуется, фоновая задача завершается.

## 7. Порядок работ

Каждый шаг оставляет программу рабочей:

1. Тестовые данные; `peaks.py`; исправления двух ошибок UI.
2. Ядро: `reference.py`, кольцевое выравнивание, `clones.py`, `.ab1proj`,
   отчёты.
3. Интерфейс: тема и иконки, разбиение `main_window.py`, фоновые задачи,
   экран «Проверка конструкта», окно группировки.
4. CLI.

## 8. Вне рамок

Планшеты на 96 ридов разных конструктов; автопоиск ORF в FASTA; `.scf`;
экспорт из Benchling; mafft/MSA; сборка контигов.
